# Defendra — UX для человека, который не админ

Это главный документ по голосу и экранам. Если `SPEC.md` и этот файл спорят про текст на экране — прав этот файл. Про безопасность сервера — `SPEC.md`.

Пользователь: купил VDS, пароль root в письме, Windows или Mac, SSH видит первый раз. Не читает длинные абзацы. Паникует, если курсор мигает без текста. Команды копирует целиком. Если сайт не открылся — гуглит `ufw disable`.

Defendra должна вести его как банковское приложение: один шаг, одна просьба, одна следующая команда. Никогда не «смотрите man ufw».

## 1. Голос

- Русский. Короткие предложения. Глагол в начале: «Откройте», «Вставьте», «Не закрывайте».
- Жаргон — только с переводом в скобках, один раз: «файрвол (фильтр входящих подключений)».
- В интерфейсе запрещены: CIS, finding, gate, drop-in, jail, sysctl, unit, YAML, JSON, stderr, reload, hash, UID.
- Можно: сервер, вход, пароль, ключ, файрвол, сайт, консоль хостера, защита, подбор пароля.
- Цвет не единственный смысл: писать «порядок» / «не полностью» / «опасно», не только зелёный кружок.
- Ошибки Debian/apt не показывать сырыми. Обернуть: «Не получилось поставить пакеты. Сеть или репозиторий Ubuntu. Попробуйте через 5 минут: sudo defendra protect».
- Никаких стеков Go. Никакого `Usage: defendra [command] [--flags]`.
- Один вопрос за раз. Enter = да.
- Принимать ответы: пусто, `да`, `д`, `yes`, `y`. Нет: `нет`, `н`, `no`, `n`. Остальное: «Напишите да или нет».
- `Y/n` не используем — для новичка это иероглифы.

## 2. Два компьютера

Человек путает «окно на моём ПК» и «окно сервера». Каждая инструкция помечает где выполнять.

```text
НА СВОЁМ КОМПЬЮТЕРЕ:
  ssh root@203.0.113.10

НА СЕРВЕРЕ (после того как вошли):
  sudo defendra protect
```

Запрещено писать «выполните ssh-keygen» без «на своём компьютере, не на сервере».

## 3. Путь от покупки VDS до «сервер защищён»

Это путь в README. Defendra его не автоматизирует до установки, но тексты должны совпадать.

### 3.1 Первый вход (ещё нет Defendra)

НА СВОЁМ КОМПЬЮТЕРЕ.

**Windows 10/11:** Пуск → пишете `powershell` → Enter.

**Mac:** Программы → Утилиты → Терминал.

```text
ssh root@СЮДА_IP_ИЗ_ПИСЬМА
```

Дальше три типичных шока — предупредить заранее, в README и в `defendra help`:

1. Спросят `Are you sure you want to continue connecting` — напишите `yes` и Enter. Это нормально один раз.
2. `Password:` — пароль из письма хостера. **Буквы не отображаются**, курсор не двигается. Это нормально. Вставили, Enter.
3. Ошибся паролем — не видно что ввели. Просто Enter и попробовать снова. Копировать пароль без пробела в конце.

Вошли, если слева что-то вроде `root@vm:~#`.

### 3.2 Установка (уже на сервере)

```text
curl -fsSL https://github.com/johnkaine45/defendra/releases/latest/download/defendra_amd64.deb -o defendra_amd64.deb
curl -fsSL https://github.com/johnkaine45/defendra/releases/latest/download/defendra_amd64.deb.sha256 -o defendra_amd64.deb.sha256
sha256sum -c defendra_amd64.deb.sha256
sudo apt install ./defendra_amd64.deb
```

Если `curl: command not found` — в README запасные строки с `wget`. Defendra при отсутствии обоих не при чём: это до неё. В help: «если пишет curl: command not found, выполните sudo apt install curl и повторите».

Если процессор ARM — другой файл `defendra_arm64.deb`. Детект в README: «если не ставится — пришлите вывод команды uname -m». Для тупого пользователя в будущем install-скрипт сам выберет файл. В v1 в help есть обе ссылки.

### 3.3 Запуск

```text
sudo defendra protect
```

Дальше только экраны из §5. Человек не должен открывать ни один другой сайт, кроме панели хостера в конце.

## 4. Команда без аргументов и справка

`defendra` без аргументов — не список флагов. Это меню.

Если protect ещё не делали:

```text
Defendra — защита Ubuntu-сервера

Сейчас нужно одно:
  sudo defendra protect

Справка, если застряли:
  defendra help
```

Если protect уже был:

```text
Defendra — сервер защищён не полностью

Что обычно нужно:
  sudo defendra status         всё ли в порядке
  sudo defendra protect        дожать защиту
  sudo defendra allow-site     открыть сайт (порты 80 и 443)
  defendra how-to-login        как заходить
  defendra help                если не входит, нет сайта, забыли пароль
```

`defendra help` — одна простыня FAQ, не man. Темы внутри одним экраном:

- не вхожу по SSH;
- буквы пароля не печатаются;
- сайт не открывается;
- какой из двух паролей;
- как открыть консоль у хостера;
- случайно закрыл окно;
- ключ, PuTTY, Termius.

`defendra how-to-login` — только про вход, крупно, без FAQ.

`defendra scan` и `defendra explain ID` не показываем в меню новичка. Они есть для нас. В help не рекламируем.

Опечатка `centra` / кириллическая `а` в `defendra`: если команда не найдена — это уже shell. В README: команда латинскими буквами `defendra`.

Запуск без sudo, когда нужен root:

```text
Эту команду нужно запустить так:

  sudo defendra protect
```

Не: `permission denied`.

Запуск не на Ubuntu:

```text
Defendra пока умеет только Ubuntu 22.04, 24.04 и 26.04.
Сейчас на этой машине: Debian 12.
Ставить защиту сюда нельзя — можно сломать вход.
```

Запуск на машине с графическим Ubuntu Desktop:

```text
Похоже, это не VDS, а обычный компьютер с Ubuntu.
Defendra для облачного сервера. Здесь запускать не нужно:
можно закрыть себе вход.

Если это всё-таки сервер — напишите да.
```

По умолчанию нет.

## 5. Экраны protect

Прогресс всегда виден. Apt может идти 3 минуты — без спиннера новичок решает, что зависло, и жмёт Ctrl+C.

```text
Defendra • шаг 2 из 9   Ставлю защиту от подбора пароля…
```

Нумерация человеческая, не имена пакетов.

### 5.1 Старт, ключ уже есть

Не стена из семи буллетов. Три строки что будет + одна что от него:

```text
Настрою этот сервер так, чтобы с улицы не подбирали пароль
и не лезли в базы.

Будет пользователь admin. Вход — по ключу, как сейчас у root.
Фильтр входящих подключений включу. Пароль SSH выключу.

Это не щит от большой атаки на канал. Её включает хостер в панели.

Продолжить? Нажмите Enter или напишите да / нет
```

### 5.2 Ключа нет — единственный сложный экран

Сначала зачем, потом где, потом что вставить. Не мешать Windows и Mac в кашу: спросить одно:

```text
Сейчас на сервер пускают по паролю. Так его взламывают за ночь.
Чтобы закрыть пароль, нужен ключ с ВАШЕГО компьютера.

На каком компьютере вы сейчас сидите?
  1 — Windows
  2 — Mac
  3 — ключ уже есть, просто вставлю
  4 — пока без ключа, сделайте что можно
```

Дальше одна инструкция под выбор.

Windows (PowerShell):

```text
НА СВОЁМ КОМПЬЮТЕРЕ откройте другое окно PowerShell
(это окно сервера не трогайте) и вставьте:

  ssh-keygen -t ed25519 -N "" -f $env:USERPROFILE\.ssh\id_ed25519

Enter, если спросит перезаписать — нет, если ключ уже был.
Потом:

  type $env:USERPROFILE\.ssh\id_ed25519.pub

Скопируйте ОДНУ строку, она начинается с ssh-ed25519.
Вернитесь СЮДА и вставьте её. Enter.
```

Если `ssh-keygen` не найден (старый Windows): текст про PuTTY или «установите OpenSSH: Параметры → Приложения → Дополнительные компоненты → OpenSSH клиент» — коротко, плюс вариант 4.

Mac: `ssh-keygen -t ed25519 -N ""` и `cat ~/.ssh/id_ed25519.pub`.

Вариант 4: частичная защита, жёлтый статус, не выключаем пароль. Прямо сказать:

```text
Сделаю файрвол и защиту от подбора. Пароль SSH пока останется.
Это лучше, чем ничего, но сервер ещё не закрыт.
Когда будет ключ — снова запустите: sudo defendra protect
```

### 5.3 Вставка ключа — проверка

- Обрезать пробелы, кавычки, `cmd:` префиксы.
- Если несколько строк — взять ту, что начинается с `ssh-ed25519` / `ssh-rsa` / `ecdsa-sha2` / `ssh-ed25519`.
- Если видит `BEGIN OPENSSH PRIVATE KEY` / `BEGIN RSA PRIVATE KEY`:

```text
Это закрытый ключ. Его нельзя никому показывать и нельзя класть на сервер.
Нужна другая строка, из файла .pub — она короткая и начинается с ssh-ed25519.
```

- Слишком короткое / битая base64: «Похоже, строка обрезалась. Скопируйте её целиком ещё раз».
- После успешной вставки — показать пальцы ключа человечески: «Ключ принят: SHA256:xxxx (это не пароль)».

Ключ на сервере не генерируем.

### 5.4 Панель управления хостера

Многие русские VDS уже с FastPanel / ISPmanager / Hestia. Если включить файрвол и не открыть порт панели — человек решит, что «сервер сломался».

Детект по процессу и порту (не настраиваем саму панель):

| Что нашли | Порт |
|---|---|
| FastPanel / aaPanel | 8888 |
| ISPmanager | 1500 |
| Hestia / Vesta | 8083 |
| Webmin | 10000 |
| Plesk | 8443 |
| CyberPanel | 8090 |
| Cockpit | 9090 |

Один вопрос, по умолчанию да:

```text
На сервере есть панель управления (заходите в неё через браузер),
порт 8888.

Оставить к ней доступ из интернета?
Если не знаете — нажмите Enter (да). Иначе панель перестанет открываться.
```

Enter = открыть порт панели в файрволе. «Нет» — порт не оставляем в leftover, с улицы панель не откроется. В status: «панель на порту 8888 открыта снаружи — это удобно, но слабое место. Пароль панели должен быть сложным».

Не открываем «на всякий случай» 8888, если панели нет.

### 5.5 Ctrl+C посредине

```text
Остановлено. Настройка могла остаться наполовину.
Это не страшно. Запустите ещё раз:

  sudo defendra protect

Повторять безопасно. Если вдруг не входите по SSH —
консоль в панели хостера и команда: sudo defendra undo
```

### 5.6 Конец, если SSH закрыли — ритуал

Крупно, пустые строки, без других советов на этом экране. Сначала вход, потом пароли.

```text
Готово. Пароль SSH выключен.

1. ЭТО ОКНО НЕ ЗАКРЫВАЙТЕ.
2. Откройте ДРУГОЕ окно на своём компьютере (не в панели хостера).
3. Введите:

   ssh admin@203.0.113.10

Если вошли — это окно можно закрыть.
Если не вошли — см. ниже, не перезагружайте сервер.
```

Следующим экраном, после паузы или тем же выводом ниже — таблица паролей (§6) и спасение через консоль.

### 5.7 Конец, если ключа не было

```text
Частично готово. Подбор пароля уже усложнён, файрвол включён.
Вход по паролю ещё работает — сервер не закрыт до конца.

Когда будет ключ:
  sudo defendra protect
```

## 6. Два пароля — главная путаница

После protect всегда показывать таблицу. Сохранить в `how-to-login`.

```text
Какой пароль для чего

  Войти по SSH с компьютера     пароль НЕ нужен, только ключ
  Команда sudo на сервере       пароль, который только что показала Defendra
                                (запишите в блокнот на компьютере, не в Telegram)
  Консоль в браузере у хостера  пароль root ИЗ ПИСЬМА хостера
                                его Defendra не меняла
```

Пароль sudo показать один раз рамкой из ASCII, не в одной куче с логом apt.

```text
┌─ пароль для sudo, один раз ─────────────┐
│  xK7!....                               │
│  запишите и храните как пароль от почты │
└─────────────────────────────────────────┘
```

Напоминание: «через SSH этот пароль не спрашивают. Он нужен, когда на сервере пишете sudo».

## 7. status для новичка

Не список ID. Три цвета словами и одна следующая команда.

```text
Defendra • порядок

  Вход           по ключу, пользователь admin
  Фильтр         включён, снаружи: 22
  Подбор пароля  сегодня отбито 412 попыток
  Обновления     ставятся сами
  Базы           из интернета не видны

  DDoS канала    это не Defendra. В панели VDS включите защиту хостера.

Как заходить:  ssh admin@203.0.113.10
Справка:       defendra help
```

Жёлтый — одна причина, одна команда:

```text
Defendra • не полностью

Ещё пускает по паролю. Нужен ключ, потом:

  sudo defendra protect

Зачем: defendra help
```

Красный:

```text
Defendra • опасно

С улицы снова виден Redis (база на порту 6379).

  sudo defendra protect
```

Сайт не открывается, хотя nginx есть:

```text
Defendra • не полностью

Сайт запущен, но фильтр его не пускает.

  sudo defendra allow-site
```

Никогда не советовать `ufw disable`, `ufw reset`, `iptables -F`.

## 8. Каталог ошибок человека

Defendra узнаёт что может; остальное — тексты в `help`. Реакция всегда: что случилось → что сделать → одной командой.

| Что сделал человек | Что видит / должен увидеть |
|---|---|
| `defendra protect` без sudo | «запустите: sudo defendra protect» |
| Запустил на ноутбуке с Ubuntu | предупреждение desktop, по умолчанию отказ |
| Вставил приватный ключ | отказ, объяснить `.pub` |
| Обрезал ключ при копировании | «строка обрезалась, вставьте целиком» |
| Сгенерировал ключ на сервере | не предлагаем этот путь; help: «ключ на сервере не поможет войти с компьютера» |
| Закрыл окно сразу после protect | help: консоль хостера → `sudo defendra undo` или войти ключом с того ПК, где ключ |
| `ssh root@...` после protect | «root по SSH закрыт. Входите: ssh admin@IP». Если попадают в help — эта строка первой |
| `Permission denied (publickey)` | «вход с того компьютера, где делали ключ. Или консоль хостера» |
| Пароль не видно при вводе | help: «так и надо, вводите вслепую» |
| Сайт не открывается | если 80 слушает — allow-site; если не слушает — «сначала поставьте nginx, потом allow-site» |
| Открыл 80 руками через ufw disable | watch красный, protect включает обратно, help: «не выключайте фильтр, для сайта есть allow-site» |
| Не тот пользователь Windows, ключ в другом профиле | help: ключ лежит в C:\Users\ИМЯ\.ssh\ |
| PuTTY и .ppk | help: короткий путь экспорта OpenSSH public key из PuTTYgen |
| Termius / телефон | help: «добавьте тот же ключ в приложение, хост admin@IP» |
| Забанен своим IP fail2ban | не банить текущий IP сессии; help: консоль хостера, подождать час или undo |
| `apt` 3 минуты молчит | не молчит: «шаг 2 из 9» |
| Кириллица в команде `ѕentra` | README: только латиница |
| Думает, что пароль из письма теперь не работает нигде | таблица §6: для консоли хостера работает |
| Перезагрузил VDS из панели «на всякий случай» | не должно ломать; status после ребута тот же |
| Поставил Docker `-p 6379:6379` на второй день | watch: «Docker выставил порт 6379 наружу. sudo defendra protect» (после v1 можно уточнить «это Docker»; в v1 достаточно «открылся порт») |

## 9. Спасение

Порядок в help и в ритуале одинаковый:

```text
Не входите с компьютера?

1. Откройте панель хостера (сайт, где покупали сервер).
2. Найдите «консоль», «VNC», «KVM», «browser console».
3. Войдите как root, пароль ИЗ ПИСЬМА хостера (буквы снова не видны).
4. Выполните:  sudo defendra undo
5. С компьютера: ssh admin@IP  с того компьютера, где ключ.
   Root по SSH после защиты закрыт. Вы уже в консоли хостера — сервер не потерян.
```

Не писать «KVM гипервизор». «Консоль в браузере у хостера» — главный термин.

## 10. allow-site

```text
Открою сайту порты 80 и 443. Фильтр останется включённым.
SSH не трогаю.

Продолжить? Нажмите Enter или напишите да / нет
```

После:

```text
Готово. Сайт из интернета может принимать посетителей.
Если страницы ещё нет — сначала поставьте nginx/caddy,
потом обновите DNS у регистратора. Это не Defendra.
```

Если UFW выключен: не включать втихую. «Сначала sudo defendra protect».

## 11. Чего не спрашиваем

Имя пользователя в v1 всегда `admin`, без вопроса. Флаг `--user` для нас.
SSH-порт не спрашиваем.
Разрешать ли ping — не спрашиваем.
Часовой пояс, hostname — не трогаем.
«Уровень CIS» — не существует в продукте.

## 12. MOTD

Одна строка. Без ASCII-арта.

- `Defendra: порядок. defendra status`
- `Defendra: не полностью — sudo defendra status`
- `Defendra: опасно, открылся порт 6379 — sudo defendra status`

## 13. Критерий «проработано для новичка»

Человек, который никогда не настраивал Linux, по README доходит до зелёного status без других инструкций. Если ошибается — Defendra или help говорит следующую команду, а не термин. Если паникует с входом — консоль хостера и `undo` находятся в том же тексте, что он видел в конце protect.

Проверка приёмки UX (дополнительно к SPEC §14):

1. `defendra` без аргументов — меню на русском, не cobra-help.
2. `defendra protect` без sudo — подсказывает sudo, не permission denied.
3. Вставка PRIVATE KEY — отказ с `.pub`.
4. На экране конца protect есть фраза «ЭТО ОКНО НЕ ЗАКРЫВАЙТЕ» и таблица двух паролей.
5. В интерфейсе protect нет слов UFW, fail2ban, sshd, jail.
6. Найден FastPanel — вопрос про порт, Enter = оставить.
7. help содержит блок «не вхожу».
8. Ни один экран не советует выключить файрвол.
